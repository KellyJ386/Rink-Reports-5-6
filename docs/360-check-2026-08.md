## Findings, ranked

### 1. Every generated PDF stamps times in the server's zone (bug)

13 call sites across `src/lib/notifications/pdf/` — `_components/meta-header.tsx`,
`render.tsx`, and all six module templates — format timestamps with a bare
`toLocaleString()` and no `timeZone`. These render inside cron routes, which run
UTC in production, so **every emailed and attached PDF misstates the time and can
name the wrong day**. That hits the refrigeration and air-quality logbooks, which
are regulatory records.

`CLAUDE.md` names this exact failure mode as a standing rule ("Never format a
time without an explicit `timeZone`"); the PDF layer is the one place it was
never applied. 14 further unzoned sites sit in admin history tabs
(`ice-operations`, `accident-reports`, `incident-reports`), the communications
broadcast tab, and the Dasher Boards staff UI.

Fix: thread the facility timezone into `PdfMetaHeaderData` and the per-template
`fmt()` helpers, using `src/lib/timezone.ts`.

### 2. Dasher Boards was never threaded into exports or retention (gap)

The module is otherwise complete — walk flow, perimeter editor, offline replay,
its own PDF template, permissions, e2e spec 12. But:

- no entry in `BUILDERS` or `EXPORTABLE_MODULES` (`src/lib/exports/module-config.ts`)
- no entry in `MODULE_COLUMN_OPTIONS` / `MODULE_LABELS` (`src/app/admin/exports/types.ts`)
- no entry in retention `MODULES` (`src/app/admin/retention/types.ts`)
- no branch in `purge_module_data()` and no `purge_old_dasher_boards_*()` worker

Practical effect: inspections can't be exported and never age out. Scheduling has
the mirror-image gap — `buildScheduling` exists but has no column options or
label, so it can't be configured or titled in the exports console.

### 3. The two biggest modules have no browser tests (coverage)

Scheduling is 23,766 lines — roughly a quarter of the product — and
Communications owns the entire email/notification pipeline. Neither has a
Playwright spec. Both have solid unit coverage of pure logic (8 test files for
Scheduling), so the gap is specifically end-to-end: shift publishing, swaps,
drops, broadcast sends, and routing rules are only ever exercised by hand.

### 4. Seven admin lists truncate instead of paginating (polish)

Only Daily Reports, Employees, Ice Depth, and Refrigeration use
`src/lib/pagination.ts`. The rest cap at a hard `.limit(200)` — or, for Dasher
Boards' inspections query, nothing at all. Data past the cap isn't slow, it's
absent, with no indication anything was cut.

## Method and limits

Dependencies installed from the lockfile, then all four gates run locally. Each
module key was traced through the eight cross-cutting systems it should appear
in. Percentages are the fraction of those systems a module is actually wired
into, adjusted for deliberate exclusions (e.g. scheduling's online-only writes
and unsupported manual purge). The headline figure weights each module by its
combined staff + admin line count.

**Not covered:** nothing was run against a live database or the production
deployment. Operator-side data gaps — unpublished shifts, unconfigured retention
policies, missing refrigeration thresholds — remain the domain of the July
functionality check.
