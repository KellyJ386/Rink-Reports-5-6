## The findings, and what was done

### 1. Every generated PDF stamped times in the server's zone — FIXED

14 sites across `src/lib/notifications/pdf/` and `src/lib/exports/pdf.tsx`
formatted timestamps with a bare `toLocaleString()` and no `timeZone`. These
render server-side, mostly from cron routes, which run UTC in production — so
every emailed and attached PDF misstated the time, and a late-evening
submission was reported on the following day. That hit the refrigeration and
air-quality logbooks, which are regulatory records.

`CLAUDE.md` already carried the rule; the PDF layer was the one place it had
never been applied.

Fixed by adding `timezone` to the single `facilities` query `resolveMetaHeader`
already made, which put the zone in scope in every template with no new
queries. Seven near-identical local helpers were replaced by one pure,
unit-tested `formatPdfTimestamp` / `formatPdfGeneratedAt` pair — the PDF layer
had zero tests before this. The new day-boundary test fails against the old
behavior.

A further 13 unzoned display sites outside the PDF layer were fixed in the same
pass: three admin history tabs now take the facility zone (they had disagreed
with their own detail views), and the client-side sites use `LocalDateTime`.
`condition-map`'s `cacheSavedAt` deliberately stays on the viewer's clock — it
is when that device wrote its offline cache.

No unguarded `toLocale*` call now remains anywhere in `src/`.

### 2. Dasher Boards was never threaded into exports or retention — FIXED

The module had no export builder (the only submission module that could not be
exported) and no retention entry (its data never aged out).

Adds `buildDasherBoards`, anchored on `started_at` since a walk has no
`submitted_at`, resolving failed assets to their labels rather than counting
them. Adds migration 239: a retention floor row, a `purge_module_data` branch,
and a nightly worker.

The purge deletes walks past the cutoff **and** issues that are already
resolved. Unresolved issues are exempt at any age — an open issue is a live
safety defect, not history, and `dasher_boards_issues.inspection_id` is ON
DELETE SET NULL, so purging walks alone would have stranded them. The isolation
harness asserts both the grants and the resolved-only rule.

Scheduling had the mirror gap — a builder with no column config, so its exports
were never configurable. Fixed.

### 3. The two biggest modules had no browser tests — SPECS WRITTEN, NOT RUN

`13-scheduling.spec.ts` and `14-communications.spec.ts` follow spec 12's
conventions. The shift-lifecycle RPCs and the admin Broadcast send are
deliberately not driven — the first mutate a published schedule through
online-only RPCs, the second queues real email to real staff.

**Neither spec has ever been executed.** This session has no target URL and no
seeded accounts; `playwright test --list` confirms they parse and register, and
that is the only claim being made.

### 4. Seven admin lists truncated instead of paginating — FIXED

Six modules capped their histories with nothing on screen to say rows had been
cut; Dasher Boards had no limit at all. All now use the existing
`clampShow`/`nextShow` helpers with `LoadMoreLink`.

Air Quality needed more than a window: its reading-type filter ran in memory
over the already-capped page, so a match outside the first 200 rows was
silently dropped. That filter now pre-resolves to report ids and joins the
query, so the window is honest.

The two failed-delivery lists and the pending-broadcast preview keep their caps
— they are triage queues, not browsable histories.

### 5. No cron execution audit trail — FIXED

Nothing recorded that a cron had run, so a silently dead cron was
indistinguishable from a healthy one: an empty outbox is equally consistent
with "nothing to do" and "hasn't run in three weeks".

Migration 240 adds `cron_runs` (super-admin-readable, no write policy at all,
with its own 90-day purge worker). All seven routes now go through
`withCronRoute`, which collapses an `authorize()` function and env prologue
that had been copy-pasted verbatim into each one. Recording is best-effort — an
audit trail must never be why a cron reports failure.

The wrapper builds its client inline rather than via `createAdminClient()`,
whose validation is better but which is `server-only` and would break the
existing route unit test. That test now asserts both concurrent workers reach
`cron_runs`.

### 6. Ice Operations had no PDF template — FIXED

It fell back to the generic layout, which could show payload fields but could
not show the per-item circle-check results (reduced to "Failed checks: 3") or
the follow-up thread. Both now render, failures sorted first.

### 7. Small gaps — FIXED

`facility_paperwork` is now in `MODULE_NAMES`; its grants existed in the DB
since migrations 175/193, but the guards in the permissions and roles actions
were rejecting writes the database would have accepted. No migration needed.

`loading.tsx` added to `admin/lists`, `admin/modules`, `admin/spaces`. A
`seedDefaultDasherBoardsConfig` action and card were added — seven other
modules ship one, and Dasher Boards had no bulk-seed path at all.

### 8. Error boundaries — WITHDRAWN

The original audit reported only two. That was wrong: `src/app/error.tsx` and
`src/app/reports/error.tsx` exist alongside the admin ones, so every route
group was already covered. No change made.

## Method and limits

Dependencies installed from the lockfile, then all four gates run locally after
every commit. Each module key was traced through the eight cross-cutting
systems it should appear in: offline replay, PDF registry, export builders and
column options, retention list and purge function, permissions, unit tests, and
e2e. Percentages are the fraction of those systems a module is wired into,
adjusted for deliberate exclusions. The headline weights each module by its
combined staff + admin line count.

**Not verified anywhere in this work:**

1. Migrations 239 and 240 — never applied; no Docker.
2. `supabase/tests/rls_isolation.sql` — new assertions never executed.
3. Both new Playwright specs — never executed.
4. Actual PDF output — needs a seeded record. The timezone fix is covered by
   unit tests on the pure formatter instead.
5. Any live-database or deployed-environment behavior. Operator-side data gaps
   remain the domain of the July functionality check.
